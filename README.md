# IN STUDIO 랜딩 페이지

상업 사진 스튜디오 [instudio.kr](https://www.instudio.kr) 의 스크롤 랜딩 페이지.
의존성 없는 단일 HTML 이다. 빌드 단계가 없다.

## 파일

| 경로 | 용도 |
|---|---|
| `index.html` | **소스이자 배포본.** 사진·폰트를 base64 로 내장한다. 수정은 항상 이 파일에서 한다. |
| `demoimg/` | 내장 사진의 원본. `mk_imweb.py` 가 base64 를 되짚는 데 쓴다. |
| `mk_imweb.py` | 아임웹 삽입용 변환기. 내장 사진을 아임웹 CDN 주소로 바꾼다. |
| `dist/imweb.html` | 위 변환 결과물. **직접 고치지 마라** — 항상 생성한다. |

## 아임웹에 넣기

```bash
python3 mk_imweb.py      # index.html → dist/imweb.html (약 240 KB)
```

`dist/imweb.html` 전체를 아임웹 **코드 위젯**에 붙여넣는다.
사진이 CDN 에서 따로 오므로 파일이 4.3 MB → 240 KB 로 줄어든다.
폰트는 내장을 유지한다 — 외부 요청이 0 이라 그게 더 빠르다.

## 구조

스크롤 한 번으로 전부 읽히는 단일 페이지.

```
HERO → 클라이언트 마퀴 3줄 → 카운터(조리개) → Selected Work 3D 릴
     → SERVICE → VALUE → PROCESS → 전체 클라이언트 목록 → CTA
```

### 스크롤이 렌더링을 구동한다

`scroll` 이벤트마다 1회 계산하는 방식이 아니다. 연속 rAF 루프가 돌면서
매 프레임 현재값을 목표값 쪽으로 당긴다(lerp). 요소마다 당기는 비율이
달라서 뒤 레이어가 늦게 따라오는 층이 생긴다.

동시에 스크롤 **속도**를 재서 렌더링에 먹인다. 빠르게 굴리면 사진이
늘어나고 멈추면 탄성으로 돌아온다. 릴은 가로로 움직이므로 세로 속도가
아니라 릴 자신의 가로 속도로 민다.

### 마스크 리빌의 함정

프레임은 `clip-path` 로 걷히고 안쪽 사진은 `scale(1.3)→1` 로 반대로
움직인다. 두 속도가 어긋나며 깊이가 생긴다.

**주의:** 클립으로 완전히 가려진 요소를 IntersectionObserver 로 감시하면
안 된다. IO 가 "화면에 없다"고 판정해서 여는 신호를 영영 못 받고 사라진다.
그래서 감시 대상은 안 잘린 부모(`.is-mrevp`)이고, 판정은 위 루프에서
직접 한다. 한 번 켜진 부모는 목록에서 빼므로 비용은 곧 0 이 된다.

### 한글 잘림

`.is-word` 는 리빌용 마스크라 `overflow:hidden` 이다. 여기에 디스플레이
서체의 `line-height:.88` 이 겹치면 한글 잉크가 라인박스보다 커서 위아래가
잘린다. 라틴은 안 잘려서 눈에 안 띈다. 패딩으로 클립 박스만 키우고 같은
값의 음수 마진으로 레이아웃을 되돌려 해결한다.

## 배포

정적 파일 그대로 Vercel 에 올린다.

```bash
npx vercel deploy --prod --scope in-ho
```

## 알려진 것

- 압축 후 전송량 약 3.2 MB. 사진·폰트를 전부 내장한 결과다. 모바일에서
  첫 화면까지 몇 초 걸린다. 사진을 별도 파일로 분리하면 첫 HTML 이
  60 KB 아래로 떨어진다 — 아직 안 했다.
- 모바일 레이아웃은 반응형으로 한 파일에서 처리하지만 실기기 점검은 안 했다.
